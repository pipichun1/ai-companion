## 修掉的问题

### 1. 装到错误目录也会“通过”

**现象**：把插件装进 `/root/agent-test`，`check.sh` 全部 ✅ 且退出码 0，
但容器实际挂载的是 `/opt/qqbot/astrbot-data` —— 插件根本没被加载。

**原因**：`check.sh` 只检查给定目录里的文件，没核对这个目录是不是容器在用的。

**修法**：加一步挂载一致性检查：

```
docker inspect <容器> → 找 "=> /AstrBot/data" 的宿主机路径
和传入的数据目录做 realpath 比较
不一致 → ❌ 并说明实际挂载路径
```

### 2. 卸载时把备份还原回来了

**现象**：第二次 install 会备份旧版；uninstall 又把这个备份解开，
于是“已移除”之后目录还在，用户以为没删干净。

**原因**：备份的语义是“回到上一版”，不是“卸载”。

**修法**：uninstall 直接删目录，不再解备份。备份只在重新安装时用于回滚。

## 还没验证到的

```
1. AstrBot 4.28 及更早版本（插件用了 4.29 的 web 路由 API）
2. 非 Docker 部署（脚本里 docker 相关步骤会跳过，但没实测）
3. 系统无 python3 的机器（check.sh 用 python3 校验 JSON）
4. Windows 宿主机（脚本是 bash，需要 WSL 或 Git Bash）
5. 真实第三方用户环境（权限、SELinux、反向代理）
```
